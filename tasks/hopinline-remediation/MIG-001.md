Title:
EF migration for the new columns, plus repair of corrupted participant positions

Purpose:
Add the columns MODEL-001 introduced, and repair existing data. The position repair is required because the app has two incompatible numbering schemes — `AddParticipantAsync` uses `Max(Position)+1` starting at 0 while `AdvanceLineAsync` uses `NextPosition++` starting at 1 — so any line that has been advanced already has duplicate positions in the database.

Dependencies:
MODEL-001

Consumes:
MODEL-001: the `Line.NextAdvanceAt`, `Line.ManageToken`, `Line.Version` properties and the `AutoAdvanceInterval`/`UnpauseRemaining` value converters

Produces:
The migration other tasks assume has been applied. No code artifact.

Files:
- `HopInLine/Migrations/<timestamp>_AddManageTokenAndAdvanceDeadline.cs` (new, generated)
- `HopInLine/Migrations/<timestamp>_AddManageTokenAndAdvanceDeadline.Designer.cs` (new, generated)
- `HopInLine/Migrations/ApplicationDbContextModelSnapshot.cs` (regenerated)

Requirements:
1. Generate the migration:
   `dotnet ef migrations add AddManageTokenAndAdvanceDeadline --project HopInLine`
   Expect it to add `NextAdvanceAt` (datetime2, null), `ManageToken` (nvarchar(64), not null), `Version` (uniqueidentifier, not null), alter `AutoAdvanceInterval` from `time` to `int`, alter `UnpauseRemaining` from `time` to `int` null, apply the new string max lengths, and create an index on `NextAdvanceAt`.
2. The generated `AlterColumn` for `AutoAdvanceInterval`/`UnpauseRemaining` will NOT convert `time` values to integer seconds — SQL Server cannot implicitly cast `time` to `int`. Hand-edit `Up` to do it explicitly: add a temporary int column, populate it with `DATEDIFF(SECOND, '00:00:00', OldColumn)`, drop the old column, rename the temp column. Do this for both columns.
3. Hand-edit `Up` to append these repair steps IN THIS ORDER, after the schema changes:
   a. Backfill `ManageToken` for existing rows:
      `UPDATE Lines SET ManageToken = LOWER(REPLACE(CONVERT(nvarchar(36), NEWID()), '-', '')) WHERE ManageToken = '' OR ManageToken IS NULL`
   b. Backfill `Version`: `UPDATE Lines SET Version = NEWID()`
   c. Renumber active participants per line to a dense 1..N, resolving duplicates deterministically:
      ```sql
      WITH ordered AS (
          SELECT Id, ROW_NUMBER() OVER (PARTITION BY LineId ORDER BY Position, Id) AS rn
          FROM Participants WHERE Removed = 0
      )
      UPDATE p SET p.Position = o.rn FROM Participants p JOIN ordered o ON p.Id = o.Id;
      ```
   d. Set `NextPosition` past the high-water mark for every line, counting removed participants too:
      ```sql
      UPDATE l SET l.NextPosition = ISNULL((SELECT MAX(p.Position) FROM Participants p WHERE p.LineId = l.Id), 0) + 1
      FROM Lines l;
      ```
   e. Backfill `NextAdvanceAt` for lines whose timer should be live, otherwise leave NULL:
      ```sql
      UPDATE Lines SET NextAdvanceAt = DATEADD(SECOND, AutoAdvanceInterval, CountDownStart)
      WHERE AutoAdvanceLine = 1 AND IsPaused = 0;
      ```
4. Fix the default-value mismatch inherited from migration `20250624062810`: existing rows have `AutoRestartTimerOnAdvance = 0` while `Line.cs` defaults the property to `true`, so old and new rows behave differently. Add `UPDATE Lines SET AutoRestartTimerOnAdvance = 1` to the repair block and change the column default to `1`.
5. Write a matching `Down` that drops the three new columns and reverses the two column type changes. The data repair need not be reversed.
