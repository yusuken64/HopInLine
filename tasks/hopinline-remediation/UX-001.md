Task ID:
UX-001

Model:
haiku

Title:
Fix the join form on Index and add a real NotFound page

Purpose:
`Index.razor` reports both join-failure paths with `Console.WriteLine`, which writes to the **server** console — so entering a bad code does visibly nothing at all. The input is also not trimmed or upper-cased, so a pasted code with a trailing space fails, and it is not inside a `<form>`, so pressing Enter does nothing. Separately, `EditLine.razor` navigates to `/not-found` on failure, which is not a registered Blazor route, so the user lands on the framework's generic "Sorry, there's nothing at this address" — this task adds the page that route needs.

Dependencies:
IDGEN-001

Consumes:
IDGEN-001: `IdGenerator.NormalizeId(string)` — the single normalization rule, so the join box and the lookup agree

Produces:
`/not-found` route consumed by EDIT-001 and VIEW-001 for their failure paths.

Files:
- `HopInLine/Pages/Index.razor` (edit)
- `HopInLine/Pages/NotFound.razor` (new)

Requirements:
1. Add an `<h1>` to `Index.razor` as the first element in its markup. `App.razor` contains `<FocusOnNavigate RouteData="@routeData" Selector="h1" />`, which currently matches nothing on any page, so keyboard focus is never moved on navigation. Text: `Hop In Line`.
2. Wrap the join code input and its button in a `<form>` with `@onsubmit="NavigateToJoinLine"` and `@onsubmit:preventDefault`, and change the button to `type="submit"`. Enter must submit the form.
3. Add a `string? joinError` field. In `NavigateToJoinLine`:
   - Replace **both** `Console.WriteLine` calls with `joinError = "<message>"` followed by `StateHasChanged()` where needed.
   - Normalize the input first: `var code = IdGenerator.NormalizeId(lineId ?? string.Empty);`
   - If `code` is empty, set `joinError = "Enter a line code."` and return.
   - If the line is not found, set `joinError = $"No line found with code \"{code}\"."` and return.
   - Clear `joinError = null` at the top of the method, before validating, so a retry does not show a stale message.
4. Render the error below the input when `joinError` is not null:
   `<div class="alert alert-danger" role="alert">@joinError</div>`
   `role="alert"` is required so a screen reader announces it.
5. Add `aria-describedby` on the input pointing at the error element's `id` when an error is showing, and give the input a visible `<label>` (not just a placeholder).
6. Create `HopInLine/Pages/NotFound.razor` with `@page "/not-found"`. It contains an `<h1>Line not found</h1>`, a sentence explaining the code may have been mistyped or the line deleted, and a link back to `/` reading "Start or join a line". No `@code` block, no dependency injection.

Constraints:
- Do NOT change `Index.razor`'s existing "Start a Line" navigation or its route.
- Do NOT change the `ShowOverlay`/`HideOverlay` calls or the `try/finally` that EMERG-001 added around them. Keep them exactly as they are.
- Do NOT edit `EditLine.razor` or `ViewLine.razor`; EDIT-001 and VIEW-001 own those and will point their own failure paths at `/not-found`.
- Do NOT add a catch-all route or touch `App.razor`.
- Do not add client-side validation attributes or `EditForm`/`DataAnnotations` — a plain `<form>` with `@onsubmit` is sufficient and avoids introducing a model class.
- The route must be exactly lowercase `/not-found`. Blazor routing is case-sensitive and `EditLine.razor` already navigates to that exact string.

Acceptance Criteria:
- Typing a nonexistent code and submitting shows a red inline message naming the code; nothing is written to the server console.
- Submitting an empty box shows "Enter a line code." and does not navigate.
- Pasting `"  abcd1234  "` (a valid code with surrounding spaces, lower case) navigates successfully.
- Pressing Enter in the input submits.
- Navigating to `/not-found` renders the new page, not the framework's default message.
- `Index.razor` has exactly one `<h1>`, and it is the first element.
- `dotnet build` succeeds with 0 errors.

Validation:
`dotnet build` completes with 0 errors.

Handoff:
Confirm no `Console.WriteLine` remains in `Index.razor`, and state the exact normalization expression used so EDIT-001 and VIEW-001 can match it.
